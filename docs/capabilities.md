# 能力与证据边界

下表记录当前厂商适配器的能力声明与离线证明入口。它表示可调用范围，不表示任意固件、语法或真实设备已经验收；单份配置的诊断、计划的 `issues` 和实际保存回执仍决定本次操作是否可执行。

十家厂商均注册登录、配置采集、配置解析和普通安全策略命令生成。另有仅提供连接器的平台注册项，可用 `Algosec::Vendors.names(:connector)` 查询。

| --- | --- | --- | --- | --- |
| `asa` | 有 | 未声明 | 未接入 | 有 |

“未接入”不表示底层没有 NAT 解析或命令生成。新 NAT 写入必须由厂商生成器提供实际发出的声明，再由共同验证器证明关系；缺少该证据时 `Plan` 不可执行，不能仅凭生成了文本就认定成功。现有 NAT 的声明、顺序、依赖与网络上下文未变时，可通过 `Nat::Verification.unchanged` 验证无关的安全策略操作。

内嵌 NAT 还依赖原生安全规则链中它之前的规则。当前证明保留这段前缀的声明与相对顺序：前序普通规则的新增、删除或跨越也会阻断，不能只比较 NAT 规则子序列。绝对重编号、描述修改、NAT 后方和其他规则链的变化仍按各自证明处理；前缀内变化即使可能流量不相交，目前也保守返回依赖变化，不声明已证明无关。

内嵌 NAT 的查询和效果证明同时复用 `Evaluation`，要求其所属安全规则实际首条命中。前置普通规则、部分覆盖、未知应用或用户条件，以及可能改变选择的时间条件都参与判断；转换声明存在且顺序未变，不足以证明转换对本次流量生效。

`Connector.capabilities(vendor)[:deploy]` 要求采集、解析、生成、保存命令和明确的原生保存成功声明同时存在。未声明保存确认的厂商仍可完成离线设计和读回关系检查。普通命令执行成功、交互提示符出现或配置文本看似相同，都不能替代保存完成证据。

从失败 `Result` 补录保存确认时，只接受明确的 `Net::Connector::LogError`，且全部保存命令、完成行和失败历史检查均须通过。独立完成回执已确认的原生保存事实，也不会因之后的取消或回执日志故障撤销。部署仍传播失败并保持 `uncertain`，不能以保存确认替代效果读回或日志提交。

未修订的 net-connector 0.16.0 和 0.17.0 在离线传输中存在已复现的取消边界：`on_event` 在命令响应完成后抛出 `Interrupt` 时，步骤可能尚未通过进度回调或 `Result` 交付。当前本地连接器源码新增独立的 `on_receipt:` 完成回执，Algosec 在连接器明确声明此参数时使用该入口；隔离的 0.17.0 源码副本已验证下发和保存中断后保留完成步骤、原始取消和不确定终态，完整原生保存证据也保留。该依赖修改尚未发布或替换系统安装，现有依赖仍有上述限制。

回执为空不表示设备没有写入；未交付证据不能通过重放命令补齐。进程被强制终止后，宿主仍负责恢复执行状态。

## 共同领域与算法

厂商统一输出 `AddressObject`、`ServiceObject`、`SecurityRule`、`NatRule` 和 `Rulebase`，保留原生身份、作用域与无法解释的声明。动作保留 `allow`、`deny`、`drop`、`reject`、`reset-client`、`reset-server`、`reset-both` 的区别；旧查询的 `permit`/`deny` 投影不能用于证明这些动作等价。

`Packet` 与 `TrafficSet` 保留地址族和五维流量配对，`Evaluation` 使用原生首条匹配。未解析命令、缺失应用或用户上下文、未知 DNS 学习状态和不完整规则顺序会产生未知证据。安全证明以给定区域和规则链为条件，不等于证明整个网络路径。

`OfflineCheck` 复用共同规则评估验证联合覆盖；一个查询的多个精确缺口按生成器的同一拆分契约分别生成、保存和回读。报告中的 `results` 因此可能多于查询结果数，命令文件逐段对应。声明回读保留源、目的、服务的配对，不模拟设备执行顺序；NAT 效果仍独立标注。

删除要求设备声明原生操作能力、整批行为保持，并在读回确认所删身份已不存在。未使用统计必须包含完整规则身份、连续历史窗口、命中计数和计数重置状态。零命中是审阅候选，不会自行授权改变仍然生效的访问行为。

## 收敛与迁移

收敛基于显式选择的规则身份，保留最早规则并生成必要修改和删除。相同动作本身不足以允许合并；日志、应用、用户、时间条件及精确流量并集都必须保持。对角流量组合不会被扩大为源和目的的全部组合。缺少原生删除能力时不返回可执行的部分脚本。

迁移保留规范动作和日志的 `nil`、`false`、`true` 区别。目标默认日志状态与源不同，或原生 `deny` 实际表示 `drop` 而无法表达源动作时，明确拒绝。源端完全被前序覆盖的规则不重复生成；目标已有规则和默认规则仍参加目标及范围外证明。

ASA 入口 ACL 的出口范围须由调用方显式限定，且入口必须属于实际 ACL 绑定；不会从兼容字段推断不存在的出口限制。源端只有终端默认规则时不生成一个声称迁移成功的空计划。源 NAT 的迁移目前明确受限；目标已有 NAT 必须证明与迁移流量无交集，不能仅因 NAT 声明未变就认定跨设备行为一致。安全规则保留了内嵌 NAT 标志、但没有完整转换关系时，也不能认定目标流量未经转换；当前不活跃的未来时间窗不能替代整个批准期限的证明。

向 ASA 新增入口 ACL 时，具体出口区域的开通请求通常会扩大其他出口上的行为，因此普通 Planner/Migration 会阻断。高级调用者可用 `ChangeSet::Target(to_zone: nil)` 明确批准入口 ACL 的全部出口范围，仍须通过完整变更和时间证明；命令能生成不表示具体出口范围已经得到保证。

离线迁移矩阵检查全部 100 个普通策略厂商组合：80 个组合通过原生解析与地址、服务、动作、日志核对；10 个目标 ASA 组合因出口作用域阻断，10 个目标 Hillstone 组合因源日志状态未指定而目标明确关闭阻断。源端实际解析出关闭日志的 Hillstone 和原生 drop 的 H3C 另有正向用例。这些数量限定于测试中的精确 IPv4 普通策略，不代表任意配置迁移成功率。

## 服务请求与匹配

`Policy::Request` 的 TCP/UDP 请求保留目的端口范围；其他协议目前只支持整个协议。裸 `icmp`、`47`，以及显式无限制的 `icmp/any`、`47/0-65535` 可规范化为协议请求。`any/443`、`icmp/8`、`47/80` 等无法准确表达的限制会抛出 `ArgumentError`，不会丢掉限制后继续生成。空后缀、多余分隔段及非法范围同样拒绝。直接构造 `Result`、转换 `Request::Traffic` 和调用 `Nat::ServiceQuery.coerce` 也遵守此边界。

服务对象保留配置中的 ICMP/ICMPv6 类型声明。已有解析器的 `0-65535` 和 `1-65535` 都表示无限制类型；空格或倒序端点按既有区间语义解释，匹配、索引、覆盖及策略路由/NAT 选择均包含类型 0。真正受限的 ICMP 类型不能用于证明整个协议已放行。底层 `Packet` 和 typed NAT 查询仍区分实际协议 0；旧策略请求文本中的 `0` 保留 `any` 别名。

域名查询逐个评估当前 DNS 地址，并按规范动作汇总结论；不同的 deny、drop、reset 或 reject 不会因旧 `decision` 字段相同而合并。

## 时间

时间效果证明覆盖计划时刻到无限未来，检查完整一次性窗口与开始/过期边界，使用精确时间值，保留闭区间语义。与变更流量可证明无关的周期规则不会阻断整个设备；可能影响变更的周期或不完整时间计划仍明确拒绝证明。

共同原生生成入口目前采用分钟精度；秒和小数秒不会被静默截断。设备时区独立于调用方时区，夏令时歧义无法唯一还原时拒绝生成。查询时间精度与原生生成精度是两个不同的合同。

PAN-OS 同名计划的多个非周期时间窗会累积保留；当前共同时间模型无法表达其并集时，配置标记为不完整，规则保持未知，不使用最后一个窗口代替整个计划。

ASA、H3C 的多条周期声明累积保留各自星期和时段，避免覆盖前一声明或把不同星期与时段交叉组合。这两家的绝对与周期组合，以及 H3C 的多个绝对窗口当前保留未知。Fortinet 跨午夜及同起止时间表示的 24 小时周期当前标记不完整，不按普通闭区间推定为不生效。

## NAT

Palo Alto 的新增证明覆盖主机静态 SNAT、明确地址的动态 SNAT、单目标 DNAT 及目的端口，以及同一规则内的源和目的转换。静态源转换生成 `bidirectional=no`。接口地址或会话分配、额外双向关系没有足够证据时不会推定成功。

Huawei 的新增证明覆盖主机 `nat server`、源 PAT 地址池或已知模式的复用池、单目标目的池和端口、同批源目的转换及其剩余源规则。地址池指定出口接口时还需证明相关路由。Easy-IP、未知接口或会话分配，以及多目标目的池的确定结果保证仍受限。

Huawei 服务器映射的查询与验证共用目的端口关系校验。仅声明协议时保持端口，省略内部端口时沿用外部端口；原生协议限定和固定端口转换均在配置文档往返后重新证明。参见 [Huawei nat server 命令](https://info.support.huawei.com/hedex/api/pages/EDOC1100278054/AEL11217/08/resources/dc/nat_server.html)。

Fortinet 的新增 VIP 分配会检查同批或同一 `state:` 的历史生成声明，拒绝外部地址、接口及协议/端口相交而内部转换不一致的请求。不同接口、协议或外部端口，以及交集内相同的转换仍可生成预览。这项检查不扩展 NAT 效果证明，缺乏证明的计划继续不可执行，也不替代对既有设备 VIP 的完整冲突分析。[Fortinet 端口转发示例](https://docs.fortinet.com/document/fortigate/7.2.7/administration-guide/155333/virtual-ips-with-port-forwarding)说明外部端口与内部端口的独立映射。

已有 Fortinet VIP 的查询、复用与读回保留 `portmapping-type`：默认或显式 `1-to-1` 按等长偏移证明，单个 `mappedport` 起点扩展为外部范围的长度；`m-to-n` 只有单目标端口时可证明固定端口，多目标池不能证明指定会话的端口结果。例如 `443–444 → 8443–8444` 可以证明 `443 → 8443`，不能证明 `443 → 8444`。未声明原生偏移语义的其他规则不会仅凭两端等长获得该证明。参见 [Fortinet VIP CLI](https://docs.fortinet.com/document/fortigate/6.4.5/cli-reference/293620/config-firewall-vip)和[端口范围配置](https://community.fortinet.com/fortigate-3/technical-tip-virtual-ip-vip-port-forwarding-configuration-99592)。

`server-load-balance` 的后端选择与端口语义尚未完整建模，当前解析明确保留不完整诊断，不能用于执行证明。尤其后端端口 `0` 表示保留原目的端口，不能当作固定转换到 `0`；该语义见 [Fortinet 负载均衡手册](https://fortinetweb.s3.amazonaws.com/docs.fortinet.com/v2/attachments/60c40932-1a0a-11e9-9685-f8bc1258b856/fortigate-load-balancing-56.pdf)中的 “Adding real servers from the CLI”。

动态池的 `possible_targets` 证明配置允许的分配集合和模式，不声称某个会话实际得到哪一个地址或端口。服务分段保留协议、端口与集合孔洞；数值协议 0 不等于传统文本接口的 `any` 别名。原始流先选择原生第一条规则，之后才核对转换目标。

每条 NAT 期望只证明声明的转换方向。源转换查询可携带目的转换的服务上下文，这不单独证明本设备执行了目的转换；同一规则的双向转换需分别提供期望，并核对共同的原始流。

SRX NAT rule-set 的接口限定还影响原生选择顺序；当前查询缺少完整接口上下文时，解析器保留诊断并阻断，不把接口条件扩大成整个区域。Neteye 内联 TCP/UDP 服务保留源端口与目的端口的配对。

## 文档与宿主

`Config::Document` schema 1 默认省略原文，保留完整性、来源摘要和未知条件元数据；显式 `raw: true` 的文档含受保护的原始片段，应由宿主加密。`Plan#to_h` 用于审阅；`PlanDocument` schema 2 保存重建输入，恢复后重新运行证明，不信任历史成功标记。两种文档的版本互相独立。

当前源码领域语义为 `firewall-domain-v8`，策略修订为 `algosec-policy-ruby-v27`。旧语义的配置文档和审批不能直接恢复为当前证据；历史记录保留，新配置通过重新采集或显式导入建立，从原始需求重新规划并审批。旧计划可能保留与对象组重名的生成脚本、旧地址取反语义、错误的端口关系证明、丢失组属性的候选图或缺少时区的基线，恢复时不能只重新证明其候选图。两种文档的 schema 版本保持不变；配置对象缓存保持 v82，较旧缓存从原文重建。原 0.3.0 本地交付记录描述 v2 构建包，不能作为当前源码已同步宿主的证据。

部署前分别核验源、目标的完整 `Snapshot#baseline`，包含 `time_zone`；即使正文及修订相同，时区变化也会在第一条写命令前阻断。各设备可以使用不同的批准时区。该检查不等同于 DNS 观察图一致性检查：相同正文下的域名答案、解析来源和观察时间仍需由宿主 verifier 核对，基础适配器尚未提供完整图预检。

登录、采集和执行测试使用模拟传输。隔离 PostgreSQL 测试覆盖宿主持久化、审批、令牌、恢复和短事务边界；它们不替代真实防火墙验收。发布包还需在独立 `GEM_HOME` 安装并分别加载公开入口，防止误用工作区源码。
